```
1name: Schema validation

7jobs:
8  validate:
9    runs-on: ubuntu-latest
10    steps:
11      - uses: actions/checkout@v4
12
13      - name: Install clickhousectl
14        run: curl https://clickhouse.com/cli | sh
15
16      - name: Install ClickHouse
17        run: chctl local install ${{ env.CLICKHOUSE_VERSION }}
18
19      - name: Start server
20        run: chctl local server start --name ci
21
22      - name: Apply schema
23        run: |
24          for f in clickhouse/tables/*.sql; do
25            chctl local client --name ci --queries-file "$f"
26          done
27
28      - name: Run test queries
29        run: |
30          for f in clickhouse/queries/test_*.sql; do
31            chctl local client --name ci --queries-file "$f"
32          done
33
34      - name: Stop server
35        run: chctl local server stop ci
```

Pin `CLICKHOUSE_VERSION` to match production. Upgrade it in one place and CI validates your whole schema against the new release on the next push, which is most of the confidence you need before an upgrade.

For Cloud writes from CI, set `CLICKHOUSE_API_KEY` and `CLICKHOUSE_API_SECRET` as secrets in your workflow and `chctl` picks them up automatically. Or pass them explicitly:

```
1chctl cloud auth login --api-key $CLICKHOUSE_API_KEY --api-secret $CLICKHOUSE_API_SECRET
```
