The first relational operator in the ClickHouse code base was [LIMIT](https://github.com/ClickHouse/ClickHouse/commit/f25307c662e895acadedacafb20c82bf0454f44d#diff-72183efe31769d15d999b988b3c9038a1dce3e6c193d8d4c508d72bb7c5a8ffb). Then I tried to [add a SQL parser](https://github.com/ClickHouse/ClickHouse/commit/c788fd5bcc4a247bf07e841c4d21f4706bc721c4). The first attempt tried to use boost::spirit, which failed. After a while, I made a [recursive descent parser](https://github.com/ClickHouse/ClickHouse/commit/8fc01e90d76500f35a41c699c1fcf2fb227b5ffc#diff-743448f0b435230d9e2441831ea64813424dd817793215a4d62430603b7456f8).

Interesting to point out some initial ideas that were rejected or reintroduced later. Initially, I tried to add a column with variable\-length encoded numbers. It was removed due to slowness, and only much later we introduced [custom compression codecs](https://clickhouse.com/docs/sql-reference/statements/create/table#column_compression_codec), independent of columns. Initially, I added a column type Variant containing arbitrary field values. It was also slow, and I removed it \- a better version of [Variant was added in 2025](https://clickhouse.com/docs/sql-reference/data-types/variant). I also had a fixed\-size array data type along with a variable\-size array, but I removed it due to the lack of need. Only today we are considering [adding it back](https://github.com/ClickHouse/ClickHouse/issues/105705). I believe that removing unnecessary code is more important than adding new code, and today, removing code is my favorite thing to do. You can find a [lot of commits](https://play.clickhouse.com/play?user=play#U0VMRUNUICogRlJPTSAiZ2l0X2NsaWNraG91c2UiLiJjb21taXRzIiBXSEVSRSBhdXRob3IgPSAnQWxleGV5IE1pbG92aWRvdicgT1JERVIgQlkgbGluZXNfZGVsZXRlZCAtIGxpbmVzX2FkZGVkIERFU0MgTElNSVQgMTAw) in ClickHouse titled "remove trash" and [similarly](https://play.clickhouse.com/play?user=play#U0VMRUNUICogRlJPTSAiZ2l0X2NsaWNraG91c2UiLiJjb21taXRzIiBXSEVSRSBtYXRjaChtZXNzYWdlLCAndHJhc2h8Z2FyYmFnZXxzaGl0fGNyYXAnKSBPUkRFUiBCWSBsaW5lc19kZWxldGVkIC0gbGluZXNfYWRkZWQgREVTQyBMSU1JVCAxMDA=).

Here you can see [the first real table](https://github.com/ClickHouse/ClickHouse/commit/abf4c945517006f119f1fdf1e6dd76e9598f78d0#diff-af436c56d04c855a5d91b381600f2887c716dc05752577c4afd57242522d6b24) structure tested in ClickHouse \- it is the `hits` table you can still see today in [ClickBench](https://benchmark.clickhouse.com/).

Trying to read and write this table uncovered that C\+\+ iostreams are slow, so [in this commit](https://github.com/ClickHouse/ClickHouse/commit/f6f252b8f2bc605f45b4d147dff564d9a9d9e87c#diff-556e240a7ccff5c9b38926aaf3327ca7066e66087d2143f9533289ad0519ee6b) you can see the introduction of `WriteBuffer`, `ReadBuffer`, which are still used today.

First functions in SQL [appeared here](https://github.com/ClickHouse/ClickHouse/commit/54808431ec1a725819721ed833bb16e1f2e7b139#diff-745f3b65a695320def044d03917ae84ed90e4d72f1f5f27e9462b8da47387c8c) \- arithmetic operators. And it allowed to implement the first [SELECT query interpreter](https://github.com/ClickHouse/ClickHouse/commit/420e68e7c7866a5e2874c35479c0ecc45f925358#diff-a0252c7b24b6cab6fa9376b0af26107533534e079f8b1efb224fdcf2a61e224f). At this time, the SELECT query interpreter was only accessible from a test program, but it allowed quickly implementing new [aggregate](https://github.com/ClickHouse/ClickHouse/commit/5c7ea6af1f45e6a10379c305a758d6d965228c51#diff-1987e4f438cd0f68180448b9bf34d35f2b9a0f59bc7ea9b41c7614b0b44e2d27) and regular functions, relational operators, data formats and other components.

ClickHouse server was introduced [on Mar 9, 2012](https://github.com/ClickHouse/ClickHouse/commit/d2c7aafe1436b6a4e26eb2ac29ffe4e401d52986) and clickhouse\-client [on Mar 25](https://github.com/ClickHouse/ClickHouse/commit/5a3649b1086c7468603347a9ba541823e32b962b#diff-d25929e577f94246434ba21301c0db68b0203927dfda5d03ffc9275fb29fa248). Together with the `Log`, `TinyLog`, `Merge`, `Distributed`, and `Memory` table engines, it was enough to deploy ClickHouse on production. The first deployment was to store incoming chunks of logs for further processing and for global queries on top of raw logs (this is what `Merge` and `Distributed` do). We can say that the first production usage of ClickHouse was a persistent log queue with SQL queries on top 😂
