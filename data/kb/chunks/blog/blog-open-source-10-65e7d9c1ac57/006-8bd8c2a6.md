Today, most of the database management systems are implemented on top of Postgres, Datafusion, and even ClickHouse. It might be interesting to look at how it is possible to bootstrap a DBMS out of nothing, in what steps?

The [first commits in 2009](https://play.clickhouse.com/play?user=play#U0VMRUNUICogUkVQTEFDRSAnaHR0cHM6Ly9naXRodWIuY29tL0NsaWNrSG91c2UvQ2xpY2tIb3VzZS9jb21taXQvJyB8fCBoYXNoIEFTIGhhc2gKRlJPTSBnaXRfY2xpY2tob3VzZS5jb21taXRzIFdIRVJFIHRpbWUgPj0gJzIwMDktMDUtMjggMTk6MTk6NTEnIE9SREVSIEJZIHRpbWUgTElNSVQgMTAwMA==) are related to optimizations related to other data structures in the same mono\-repository. They are visible because, during open\-sourcing, I carefully split the repository while preserving all the history.

The first commit where I started implementing a new DBMS (the name ClickHouse came later) is [here](https://github.com/ClickHouse/ClickHouse/commit/ea150ca6716fcf0de2c146b76b7045082765416b) \- the implementation of columns in memory: you can see already familiar classes IColumn and Field. Compare it to today's implementation :) You might think that this is similar to Apache Arrow (which focuses on column representation in memory), and why didn't we use it \- but Apache Arrow didn't exist then (other column\-oriented formats, such as RCFile, Trevni, ORC, and Parquet didn't exist either).

Then aggregate functions were introduced in [this commit](https://github.com/ClickHouse/ClickHouse/commit/2dbd493503cf8d50a8a5d3c08cf408d990527b1d). It is still one of the most important parts of ClickHouse.

Then table engines were introduced. It is funny that table engines were [named "primary key"](https://github.com/ClickHouse/ClickHouse/commit/5442c79092e13077d330b7a9cd75a9dbd0b02034), but only for [a few days](https://github.com/ClickHouse/ClickHouse/commit/eed5be39796c7da0ba0718e37c5960ff48de944b). This allowed reading and writing columns on disk. The [first table engine](https://github.com/ClickHouse/ClickHouse/commit/84592c521f3f9f33732e0dccaa66bfc2c2233fc4) was similar to TinyLog, which exists till today.

Then [compression was added](https://github.com/ClickHouse/ClickHouse/commit/8af888b6a93d6fcf5a5a08ddf94ac8e9ba520cd2). Initially, it was [QuickLZ](https://web.archive.org/web/20081205030319/http://www.quicklz.com/), but as soon as I read [Yann Collet's blog](https://fastcompression.blogspot.com/p/lz4.html), I replaced it with [LZ4](https://github.com/ClickHouse/ClickHouse/commit/58110f5cde5f3ececf2b439ab8cc36748559012d).

Then [block streams](https://github.com/ClickHouse/ClickHouse/commit/148b08ff1ad4165c63c5ffca912cf3027c9dad93) \- components of the data processing pipeline that produce, consume, or transform chunks of columns in a streaming form. Today, these are replaced with [Processors](https://github.com/ClickHouse/ClickHouse/blob/b5fa90e290861e96f6f22beea35326c97fe736b0/src/Processors/IProcessor.h#L32). This unlocked the way for [formatting results](https://github.com/ClickHouse/ClickHouse/commit/746b7fce5e938fff22a65d509b74364ca41340a8) and implementing queries on tables. The same commit added `StorageSystemNumbers` \- introduced for testing query pipelines, and it remains today as our beloved `system.numbers` table. The [first query pipeline](https://github.com/ClickHouse/ClickHouse/commit/746b7fce5e938fff22a65d509b74364ca41340a8) in ClickHouse was printing numbers in TSV.

[Here](https://play.clickhouse.com/play?user=play#U0VMRUNUIHRpbWUsICdodHRwczovL2dpdGh1Yi5jb20vQ2xpY2tIb3VzZS9DbGlja0hvdXNlL2NvbW1pdC8nIHx8IGNvbW1pdF9oYXNoLCBleHRyYWN0KGxpbmUsICdjbGFzcyBTdG9yYWdlXHcrJykgQVMgc3RvcmFnZSwgcGF0aCwgZmlsZV9jaGFuZ2VfdHlwZQpGUk9NIGdpdF9jbGlja2hvdXNlLmxpbmVfY2hhbmdlcyBXSEVSRSB0aW1lID49ICcyMDA5LTA1LTI4IDE5OjE5OjUxJyBBTkQgbGluZSBMSUtFICclcHVibGljIElTdG9yYWdlJScgT1JERVIgQlkgdGltZSBMSU1JVCAxIEJZIHN0b3JhZ2UgTElNSVQgMTAwMA==) you can see which table engines were introduced in what order.

The first relational operator in the ClickHouse code base was [LIMIT](https://github.com/ClickHouse/ClickHouse/commit/f25307c662e895acadedacafb20c82bf0454f44d#diff-72183efe31769d15d999b988b3c9038a1dce3e6c193d8d4c508d72bb7c5a8ffb).

Then I tried to [add a SQL parser](https://github.com/ClickHouse/ClickHouse/commit/c788fd5bcc4a247bf07e841c4d21f4706bc721c4). The first attempt tried to use boost::spirit, which failed. After a while, I made a [recursive descent parser](https://github.com/ClickHouse/ClickHouse/commit/8fc01e90d76500f35a41c699c1fcf2fb227b5ffc#diff-743448f0b435230d9e2441831ea64813424dd817793215a4d62430603b7456f8).
