Get function symbols pointers from compiled code using RuntimeDyld dynamic linker. Our wrapper interface around JIT compilation looks like this:

```
1class CHJIT
2{
3    struct CompiledModule
4    {
5        /// Size of compiled module code in bytes
6        size_t size;
7
8        /// Module identifier. Should not be changed by client
9        uint64_t identifier;
10
11        /// Map of compiled functions. Should not be changed by client
12        std::unordered_map<std::string, void *> function_name_to_symbol;
13    };
14
15    /// Compile module. Client must fill module with necessary IR code.
16    CompiledModule compileModule(std::function<void (llvm::Module &)> compile_function);
17
18    /** Delete compiled module.
19      * Pointers to functions from module become invalid after this call.
20      */
21    void deleteCompiledModule(const CompiledModule & module_info);
22
23    /// Register external symbol for CHJIT instance to use, during linking.
24    void registerExternalSymbol(const std::string & symbol_name, void * address);
25
26    /// Total compiled code size for modules that are currently valid.
27    inline size_t getCompiledCodeSize() const;
28}
```

In the implementation, our wrapper uses the same strategy as described above. Additionally it:

- Stores RTDyldMemoryManager for each compiled module to allow it to be deleted if requested.
- Sets up JITSymbolResolver with common functions that can be generated by compiler memset, memcpy, memcmp.
- Uses a custom allocator for JIT code.
- Provides thread safety.
