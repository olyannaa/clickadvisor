Finally, since the final schema required tuples, we had difficulty converting the JSON from our dataset into the right format. To address this we make use of the [Null table engine](https://clickhouse.com/docs/en/engines/table-engines/special/null), combined with a Materialized View, to do ClickHouse\-specific transformations from a JSON string to a tuple. For example, the following view and Null table are responsible for receiving inserts for the tokens dataset. The results of the Materialized View are sent to the final `solana.tokens` table:

```
1CREATE TABLE solana.stage_tokens
2(
3	`block_slot` Int64,
4	`block_hash` String,
5	`block_timestamp` DateTime64(6),
6	`tx_signature` String,
7	`retrieval_timestamp` DateTime64(6),
8	`is_nft` Bool,
9	`mint` String,
10	`update_authority` String,
11	`name` String,
12	`symbol` String,
13	`uri` String,
14	`seller_fee_basis_points` Decimal(38, 9),
15	`creators` String,
16	`primary_sale_happened` Bool,
17	`is_mutable` Bool
18)
19ENGINE = Null
20
21CREATE MATERIALIZED VIEW solana.stage_tokens_mv TO solana.tokens
22(
23	`block_slot` Int64,
24	`block_hash` String,
25	`block_timestamp` DateTime64(6),
26	`tx_signature` String,
27	`retrieval_timestamp` DateTime64(6),
28	`is_nft` Bool,
29	`mint` String,
30	`update_authority` String,
31	`name` String,
32	`symbol` String,
33	`uri` String,
34	`seller_fee_basis_points` Decimal(38, 9),
35	`creators` Array(Tuple(String, UInt8, Int64)),
36	`primary_sale_happened` Bool,
37	`is_mutable` Bool
38)
39AS SELECT block_slot, block_hash, block_timestamp, tx_signature, retrieval_timestamp, is_nft, mint, update_authority, name, symbol, uri, seller_fee_basis_points, arrayMap(x -> (x.1, (x.2) = 1, x.3), CAST(creators, 'Array(Tuple(String, Int8, Int64))')) AS creators,primary_sale_happened, is_mutable
40FROM solana.stage_tokens
```
