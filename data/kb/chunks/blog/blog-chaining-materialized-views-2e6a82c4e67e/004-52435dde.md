```
1CREATE TABLE byMinute
2(
3    dateTime DateTime64(3, 'UTC') NOT NULL,
4    users AggregateFunction(uniq, String),
5    pages AggregateFunction(uniq, String),
6    updates AggregateFunction(sum, UInt32) 
7)
8ENGINE = AggregatingMergeTree() 
9ORDER BY dateTime;
```

The materialized view that populates this table will read from `rawEvents` and use `-State` combinators to extract the intermediate state. We’ll use the `uniqState` function for users and pages and `sumState` for updates.

```
1CREATE MATERIALIZED VIEW byMinute_mv TO byMinute AS 
2SELECT toStartOfMinute(dateTime) AS dateTime,
3       uniqState(user) as users,
4       uniqState(title_url) as pages,
5       sumState(toUInt32(1)) AS updates
6FROM rawEvents
7GROUP BY dateTime;
```

We don’t have any data flowing into Kafka, so this table won’t have any data. Let’s fix that by running the following commands.

```
1curl -N https://stream.wikimedia.org/v2/stream/recentchange  |
2awk '/^data: /{gsub(/^data: /, ""); print}' |
3jq -cr --arg sep ø '[.meta.id, tostring] | join($sep)' |
4kcat -P -b localhost:9092 -t wiki_events -Kø
```
Copy command
This command extracts the `data` property from the recent changes feed, constructs a `key:value` pair using jq, and then pipes it into Kafka using kcat.

If we leave that running for a little while, we can then write a query to see how many changes are being made:
​​

```
1SELECT
2    dateTime AS dateTime,
3    uniqMerge(users) AS users,
4    uniqMerge(pages) AS pages,
5    sumMerge(updates) AS updates
6FROM byMinute
7GROUP BY dateTime
8ORDER BY dateTime DESC
9LIMIT 10;
```
