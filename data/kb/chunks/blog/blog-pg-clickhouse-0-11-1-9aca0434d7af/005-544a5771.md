### Aggregate NULL results \#

The appearance of `regr_avgyOrNull()` in the previous sample output spoils the
news, but to be clear, this release also teaches `NULL`\-returning aggregates
to actually return `NULL` rather than a ClickHouse default value (e.g., `0`)
when they aggregate no values. Rather than `sum`, `avg`, and `min`, etc.,
pg\_clickhouse now pushes down `sumOrNull`, `avgOrNull`, and `minOrNull`, thus
matching Postgres behavior:

```
1EXPLAIN (VERBOSE, COSTS OFF) SELECT SUM(id) FROM items;
```
Copy command

```
1QUERY PLAN                       
2-------------------------------------------------------
3 Foreign Scan
4   Output: (sum(id))
5   Relations: Aggregate on (items)
6   Remote SQL: SELECT sumOrNull(id) FROM default.items
7(4 rows)
```

### JSON subscript pushdown \#

JSONB subscript syntax, `data['a']['b']`, now pushes down to ClickHouse column
"dot notation":

```
1EXPLAIN (VERBOSE, COSTS OFF)
2      SELECT id FROM json_http.events WHERE props['address']['city'] = '"Paris"';
```
Copy command

```
1QUERY PLAN                                              
2------------------------------------------------------------------------------------------------------
3 Foreign Scan on json_http.events
4   Output: id
5   Remote SQL: SELECT id FROM json_test.events WHERE ((toJSONString(props.address.city) = '"Paris"'))
6(3 rows)
```

### TimeZone pushdown \#

On ClickHouse 23\.6\+, pg\_clickhouse now always sets `session_timezone` to match
the PostgreSQL `TimeZone`, and passes the PostgreSQL `TimeZone` to DateTime
functions, thus ensuring compatibility of `timestamp` and `timestamptz`
values:

```
1EXPLAIN (VERBOSE, COSTS OFF)
2      SELECT percentile_cont(0.95) WITHIN GROUP (
3        ORDER BY date_part('epoch', timezone('UTC', c))
4      ) FROM t1;
```
Copy command

```
1QUERY PLAN                                                                   
2-----------------------------------------------------------------------------------------------------------------------------------------------
3 Foreign Scan
4   Output: (percentile_cont('0.95'::double precision) WITHIN GROUP (ORDER BY (date_part('epoch'::text, timezone('UTC'::text, c)))))
5   Relations: Aggregate on (t1)
6   Remote SQL: SELECT quantileOrNull(0.95)(toUnixTimestamp(toDateTime64(toString(c, 'America/Los_Angeles'), 6, 'UTC'))) FROM functions_test.t1
7(4 rows)
```
