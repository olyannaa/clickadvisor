[pg\_clickhouse v0\.11\.1](https://github.com/ClickHouse/pg_clickhouse/releases/tag/v0.11.1) also introduces support for `UPDATE`, `DELETE`, and
`TRUNCATE` statements on [MergeTree](https://clickhouse.com/docs/reference/engines/table-engines/mergetree-family/mergetree) family tables. It pushes down `UPDATE`
and `DELETE` statements as lightweight [UPDATE](https://clickhouse.com/docs/reference/statements/update) or [DELETE](https://clickhouse.com/docs/concepts/features/operations/delete/lightweight-delete) statements,
respectively, and `TRUNCATE` statements as [TRUNCATE](https://clickhouse.com/docs/reference/statements/truncate) statements, naturally.

Let's put them to work on the `items` table. First, [UPDATE](https://clickhouse.com/docs/reference/statements/update) requires a couple
of ClickHouse settings to be enabled:

```
1CALL clickhouse_perform('ch_server', $$
2    ALTER TABLE items
3    MODIFY SETTING enable_block_number_column = 1, enable_block_offset_column = 1;
4$$);
```
Copy command
And now we can make updates:

```
1UPDATE items SET v = '[1,1,1,1]' WHERE id = 0;
```
Copy command
Check our work:

```
1select * FROM items where id = 0;
```
Copy command

```
1id | category |     v     
2----+----------+-----------
3  0 | a        | [1,1,1,1]
4(1 row)
```
Copy command
Now `DELETE`:

```
1DELETE FROM items where id = 0;
```
Copy command
Is it gone? Yup:

```
1select * FROM items where id = 0;
```
Copy command

```
1id | category | v 
2----+----------+---
3(0 rows)
```
Copy command
Do be aware that PostgreSQL `UPDATE` and `DELETE`, unlike ClickHouse's, do not
require `WHERE` clauses. In the absence of a `WHERE` clause, pg\_clickhouse
inserts `WHERE true` to match the PostgreSQL behavior. But you surely don't
want to update or delete every row in a ClickHouse table! As the [docs say](https://clickhouse.com/docs/reference/statements/update):

> Lightweight updates are designed to update small amounts of rows (up to
> about 10% of the table).

Instead of deleting every row, use `TRUNCATE`:

```
1TRUNCATE items;
```

All gone:

```
1select COUNT(*) from items;
```

2-------
3     0
4(1 row)
```

## Other highlights \#

### Linear regression aggregate pushdown \#

[pg\_clickhouse v0\.11\.1](https://github.com/ClickHouse/pg_clickhouse/releases/tag/v0.11.1) also adds pushdown for the `regr_*` family of linear
regression aggregate functions on ClickHouse 26\.9 or later, when [ClickHouse added them](https://www.linkedin.com/posts/alasdair-brown_clickhouse-269-adds-the-regr-family-familiar-ugcPost-7507187538965688320-ChAW/). These include:

- [regr\_avgx](https://clickhouse.com/docs/reference/functions/aggregate-functions/regr_avgx)
- [regr\_avgy](https://clickhouse.com/docs/reference/functions/aggregate-functions/regr_avgy)
- [regr\_count](https://clickhouse.com/docs/reference/functions/aggregate-functions/regr_count)
- [regr\_intercept](https://clickhouse.com/docs/reference/functions/aggregate-functions/regr_intercept)
- [regr\_r2](https://clickhouse.com/docs/reference/functions/aggregate-functions/regr_r2)
- [regr\_slope](https://clickhouse.com/docs/reference/functions/aggregate-functions/regr_slope)
- [regr\_sxx](https://clickhouse.com/docs/reference/functions/aggregate-functions/regr_sxx)
- [regr\_sxy](https://clickhouse.com/docs/reference/functions/aggregate-functions/regr_sxy)
- [regr\_syy](https://clickhouse.com/docs/reference/functions/aggregate-functions/regr_syy)

Example:

```
1EXPLAIN (VERBOSE, COSTS OFF)
2      SELECT regr_avgy(b, a) FROM agg_bin.agg_numbers;
```
