[pg\_clickhouse v0\.11\.1](https://github.com/ClickHouse/pg_clickhouse/releases/tag/v0.11.1) also pushes down a number of [pgvector](https://github.com/pgvector/pgvector) operators and
functions, including, most simply, `=`, visible in the "Remote SQL" line from
`EXPLAIN (VERBOSE)`:

```
1EXPLAIN (COSTS OFF, VERBOSE) SELECT * FROM items WHERE v = '[0,0,0,0]';
```
Copy command

```
1QUERY PLAN                                                
2---------------------------------------------------------------------------------------------------------
3 Foreign Scan on public.items
4   Output: id, category, v
5   Remote SQL: SELECT id, category, v FROM default.items WHERE ((v = cast([0,0,0,0] as Array(Float32))))
6(3 rows)
```
Copy command
The results come as no surprise:

```
1SELECT * FROM items WHERE v = '[0,0,0,0]';
```
Copy command

```

2----+----------+-----------
3  0 | a        | [0,0,0,0]
4(1 row)
```

Even better, pg\_clickhouse pushes down the [pgvector distance operators](https://pgxn.org/dist/vector/#Querying). For
example, `<->` pushes down to the ClickHouse [L2Distance](https://clickhouse.com/docs/reference/functions/regular-functions/distance-functions#L2Distance) function once again
visible in the "Remote SQL" line from `EXPLAIN (VERBOSE)`:

```
1EXPLAIN (VERBOSE, COSTS OFF)
2SELECT id FROM items ORDER BY v <-> '[0.3,-0.2,0.5,0.1]' LIMIT 5;
```
Copy command

```
1QUERY PLAN                                                                
2-----------------------------------------------------------------------------------------------------------------------------------------
3 Foreign Scan on public.items
4   Output: id, (v <-> '[0.3,-0.2,0.5,0.1]'::vector)
5   Vector Search: L2Distance on v
6   Vector Index: none
7   Vector Index Not Used: column "v" has no vector index
8   Remote SQL: SELECT id, v FROM default.items ORDER BY L2Distance(v, cast([0.3,-0.2,0.5,0.1] as Array(Float32))) ASC NULLS LAST LIMIT 5
9(6 rows)
```
