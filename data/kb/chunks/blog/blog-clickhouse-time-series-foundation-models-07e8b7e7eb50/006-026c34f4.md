selects how many trailing observations receive scores; it does not limit the history available to the model. The result is aligned with the original series, so it can be combined with its dates and observed units using `arrayZip`:

```
1SELECT
2    store_id,
3    point.1 AS day,
4    point.2 AS observed,
5    point.3.expected AS expected,
6    point.3.anomaly_score AS anomaly_score
7FROM
8(
9    SELECT
10        store_id,
11        arrayJoin(arrayZip(
12            arrayMap(p -> p.1, points),
13            arrayMap(p -> p.2, points),
14            aiDetectAnomalies(
15                arrayMap(p -> p.2, points),
16                '{"score_last_n":180,"horizon":7,"threshold":3}'
17            )
18        )) AS point
19    FROM
20    (
21        SELECT
22            store_id,
23            arraySort(p -> p.1, groupArray((day, units))) AS points
24        FROM m5.store_daily
25        WHERE day >= toDate('2013-10-28')
26        GROUP BY store_id
27    )
28)
29WHERE point.3.is_anomaly = 1
30ORDER BY anomaly_score DESC
31LIMIT 10
32SETTINGS max_threads = 1;
```

The function returns `(expected, lower_bound, upper_bound, anomaly_score, is_anomaly)` for each input observation. Unscored context positions have null predictions and scores. The score is the absolute forecast error divided by the distance from the median to the interval bound on that side, with a numerical floor. It is not a probability: `threshold=3` filters scores above 3 rather than specifying a confidence level.

Anomaly scores always use `q10` and `q90` as their reference bounds. Selecting a different forecast quantile or interval for another query does not change that reference, the scores, or the anomaly threshold.
