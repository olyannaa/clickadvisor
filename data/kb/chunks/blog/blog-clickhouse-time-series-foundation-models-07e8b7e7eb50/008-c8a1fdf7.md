reproduction script loads `m5.event_calendar` from M5's `calendar.csv`, with one row per date. For this experiment, `is_event_day=1` when either event\-name field is `Christmas`, and 0 otherwise. Joining the calendar to sales keeps the selected event aligned with each observation:

```
1WITH ordered_store_history AS (
2    SELECT
3        s.store_id AS store_id,
4        arraySort(p -> p.1,
5            groupArray((s.day, s.units, c.is_event_day))
6        ) AS points
7    FROM m5.store_daily AS s
8    INNER JOIN m5.event_calendar AS c ON s.day = c.day
9    WHERE s.day >= toDate('2013-10-28')
10      AND s.day < toDate('2015-12-30')
11    GROUP BY s.store_id
12),
13store_series AS (
14    SELECT
15        store_id,
16        arrayMap(p -> p.1, points) AS days,
17        arrayMap(p -> p.2, points) AS observed_units,
18        arrayMap(p -> toFloat64(p.3), points) AS event_flags
19    FROM ordered_store_history
20),
21scoring_requests AS (
22    SELECT
23        store_id,
24        days,
25        observed_units,
26        arrayJoin([0, 1]) AS with_calendar,
27        toJSONString(CAST(
28            (7, 7, 3, if(with_calendar = 1,
29                [event_flags], CAST([], 'Array(Array(Float64))'))),
30            'Tuple(score_last_n UInt32, horizon UInt32, threshold Float64, future_covariates Array(Array(Float64)))'
31        )) AS options_json
32    FROM store_series
33),
34scored_history AS (
35    SELECT
36        store_id,
37        with_calendar,
38        days,
39        observed_units,
40        aiDetectAnomalies(observed_units, options_json) AS scores
41    FROM scoring_requests
42)
43SELECT
44    store_id,
45    any(observed) AS observed_units,
46    round(maxIf(score.expected, with_calendar = 0), 0) AS history_only_median,
47    round(maxIf(score.expected, with_calendar = 1), 0) AS with_calendar_median,
48    round(maxIf(score.anomaly_score, with_calendar = 0), 2) AS history_only_score,
49    round(maxIf(score.anomaly_score, with_calendar = 1), 2) AS with_calendar_score
50FROM scored_history AS h
51ARRAY JOIN
52    h.days AS day,
53    h.observed_units AS observed,
54    h.scores AS score
55WHERE day = toDate('2015-12-25')
56GROUP BY store_id
57ORDER BY store_id
58SETTINGS max_threads = 1;
```

`toJSONString` serializes the named tuple into the options object. Its `future_covariates` field contains one feature array: `is_event_day`. There are no past\-only features, so `past_covariates` is omitted. The scoring service can see the event schedule for December 23–29 without seeing those days' sales. All that to say that this is how to provide the model with known future events to consider when producing a forecast.
