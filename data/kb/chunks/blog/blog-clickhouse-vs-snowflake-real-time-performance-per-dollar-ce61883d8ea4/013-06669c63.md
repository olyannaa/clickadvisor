A working set that exceeds cache capacity requires more remote reads. Warehouse sizing therefore affects both cache capacity and cost.

**WARMING THROUGHPUT**

Snowflake documents roughly [300–400 MB/s](https://docs.snowflake.com/en/user-guide/interactive#resuming-and-suspending-an-interactive-warehouse) of warming throughput even for X\-Small, with larger warehouses warming faster. That exceeds the earlier workload’s roughly 75 MB/s ingest rate. At higher source rates, recently arrived data may require remote reads even when the total working set still fits.

**SIZING IMPLICATION**

The Interactive Warehouse must be sized for both the data queries touch and the rate at which new data arrives. ClickHouse’s query path reads the ordered MergeTree table without a separately populated Interactive Warehouse serving cache.

> Across the drill\-down workload, ClickHouse Cloud was 1\.48× faster overall.

### Interactive aggregations over ordered pre\-aggregated data \#

Daily pre\-aggregations let [A1–A4](https://github.com/ClickHouse/CostBench/blob/main/full-path-realtime/quotes/clickhouse-cloud/queries_mv.sql) combine prepared counts, sums, and price minima and maxima. A1–A2 filter the ordered summaries by symbol; A3–A4 read across all symbols. ClickHouse reads current summaries; Snowflake must also include newer rows. The chart below shows the resulting latency gap as data accumulates.

**ClickHouse Cloud:**

- 13 ms median \- 801× faster than Snowflake
- 42 ms P99 \- 533× faster
- 111 ms maximum \- 218× faster

Accumulated runtime was 11\.36 seconds.

**Snowflake:**

- 10\.41 s median
- 22\.20 s P99
- 24\.17 s maximum

Snowflake’s sawtooth curves rise as rows accumulate between refreshes and fall when refreshes catch up. Accumulated runtime was 2\.11 hours. Under the benchmark’s five\-second fallback proxy, [477 of 836 executions (57%)](https://github.com/ClickHouse/CostBench/blob/main/full-path-realtime/quotes/snowflake/costs/out/t2/run14/dashboard.json) were priced at the fallback rate.

> Across the interactive\-aggregation workload, ClickHouse Cloud was 669× faster overall.

### Accumulated query cost and runtime \#

Those per\-query differences accumulate: interactive aggregations account for most of the gap. The charts below combine both workloads and price their measured runtimes using the benchmark’s read\-side cost model.

ClickHouse Cloud accumulated 1\.03 minutes of query runtime and Snowflake 2\.13 hours. Their normalized query\-serving costs were about $0\.05 and $15\.99, respectively. These are normalized costs for the query work, not complete warehouse invoices.

> Across the query workload, ClickHouse Cloud was 124× faster overall, with 298× lower normalized query cost.
