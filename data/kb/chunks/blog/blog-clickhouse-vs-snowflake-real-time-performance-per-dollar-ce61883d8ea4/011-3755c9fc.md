**COST EXCLUSIONS**

Standing fallback capacity, minimum billing, idle capacity, and an additional primary\-warehouse charge for fallback\-priced queries are excluded. Full\-duration timing is retained; no query phase is removed from latency or normalized cost. The pricing note below provides the rates and calculation.

> The result: drill\-downs prune ordered raw data; interactive aggregations catch up on read when summaries lag.

## What this means for query performance and cost \#

### Drill\-downs over ordered raw data \#

Both systems order raw data as it arrives, so drill\-downs can prune unrelated data. **QUERY DEFINITIONS**

[Part 1](https://clickhouse.com/blog/costbench-real-time-performance-per-dollar) [explains](https://clickhouse.com/blog/costbench-real-time-performance-per-dollar#how-costbench-keeps-the-comparison-fair) the four aggregate queries A1–A4 and two drill\-downs D1–D2, including how newly ingested quotes contribute to their answers. Both systems used the same query semantics and schedule.

**CACHE POLICY**

Query\-result caching was disabled, so every measured query ran. Underlying data caches were allowed to remain warm. Both systems used the read\-side sizing described in the methodology note.

**TIMING**

Latency and accumulated runtime use each query’s full client\-visible duration. Per\-query median, P99, and maximum statistics summarize unsmoothed observations through 100 billion rows.

**LATENCY CHARTS**

Each system is plotted against its own observed row counts, rather than equal iteration numbers or interpolation between systems. Aggregate trends use a centered seven\-observation rolling median; [drill\-down trends](https://github.com/ClickHouse/CostBench/blob/main/full-path-realtime/quotes/snowflake/results/t2/charts/run14/drilldown_query_latency_clickhouse_vs_snowflake_wide_summary.json) use a centered five\-observation rolling median. The [aggregate chart](https://github.com/ClickHouse/CostBench/blob/main/full-path-realtime/quotes/snowflake/results/t2/charts/run14/aggregate_query_latency_clickhouse_vs_snowflake_wide_summary.json) retains its Snowflake\-only Tukey upper\-fence rule, with excluded points retained in the source and summary.
