for the lambda \# The code to address this challenge is quite simple. The only thing to remember is that the virtual environment should be created with the same Python version as the one used by AWS Lambda.

```
1docker_cmd=(
2  docker run -i --net=host --rm --user="${UID}" -e HOME=/tmp --entrypoint=/bin/bash
3  --volume="${WORKDIR}/..:/ci" --workdir="/ci/${DIR_NAME}" "${DOCKER_IMAGE}"
4)
5rm -rf "$PACKAGE" "$PACKAGE".zip
6mkdir "$PACKAGE"
7cp app.py "$PACKAGE"
8if [ -f requirements.txt ]; then
9  VENV=lambda-venv
10  rm -rf "$VENV"
11  "${docker_cmd[@]}" -ex <<EOF
12    '$PY_EXEC' -m venv '$VENV' &&
13    source '$VENV/bin/activate' &&
14    pip install -r requirements.txt &&
15    # To have consistent pyc files
16    find '$VENV/lib' -name '*.pyc' -delete
17    cp -rT '$VENV/lib/$PY_EXEC/site-packages/' '$PACKAGE'
18    rm -r '$PACKAGE'/{pip,pip-*,setuptools,setuptools-*}
19    chmod 0777 -R '$PACKAGE'
20EOF
21fi
```
Copy command
Here we check if the lambda function has a `requirements.txt` file. If it does, we create a virtual environment with the same Python version as the one used by AWS Lambda, install the dependencies, and copy the site\-packages to the lambda package directory. To remove the unnecessary files, we delete the `pip` and `setuptools` directories as well as Python byte\-code files.

## Conclusion \#

The full script doing the job is available [here](https://github.com/ClickHouse/ClickHouse/blob/1443e490ea5287175f031eaee567fe5024cd7306/tests/ci/team_keys_lambda/build_and_deploy_archive.sh). Later it was moved into the private repository, but it is still used in Terraform/OpenTofu configuration to deploy the lambda functions.
