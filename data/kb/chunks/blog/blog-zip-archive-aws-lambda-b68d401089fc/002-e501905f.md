Besides that, we should omit passing the directories to the zip command. Otherwise, it could cause inconsistency. The argument `-D` helps here.

So, here's the very first solved issue.

```
1export LC_ALL=c
2# zip uses random files order by default, so we sort the files alphabetically
3find . ! -type d -print0 | sort -z | tr '\0' '\n' | zip -XD -0 ../"$PACKAGE".zip --names-stdin
```
Copy command
The found files are null\-divided and sorted, and then null is replaced by a new line and passed to the ZIP.

This is the part of the man zip about one of the arguments above:

```

2   --no-extra
3           Do not save extra file attributes (Extended Attributes on OS/2,
4           uid/gid and file times on Unix).  The  zip  format  uses  extra
5           fields  to include additional information for each entry.  Some
6           extra fields are specific to particular  systems  while  others
7           are applicable to all systems.  Normally when zip reads entries
8           from  an  existing archive, it reads the extra fields it knows,
9           strips the rest, and adds the extra fields applicable  to  that
10           system.   With  -X, zip strips all old fields and only includes
11           the Unicode and Zip64 extra fields (currently these  two  extra
