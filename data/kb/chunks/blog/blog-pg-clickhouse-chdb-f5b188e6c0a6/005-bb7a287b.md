Copy command
The `goals` array contains two arrays with two text values each, the first for
`serial`, the second for `order_id`. This structure preserves the data at the
expense of its data type, although an INSERT on a pg\_clickhouse table properly
converts types before inserting into ClickHouse:

```
1INSERT INTO visits
2VALUES (2, 2, ARRAY[ ['3', 'aa'], ['4', 'bb'] ]);
```
Copy command
But we can do better. [pg\_clickhouse](https://clickhouse.com/docs/products/managed-postgres/extensions/pg_clickhouse/) v0\.11\.0 also allows Nested values to map
to custom [composite types](https://www.postgresql.org/docs/current/rowtypes.html), as long as the order, type, and naming align
perfectly. Given the Nested type defined for `goals`:

```
1Tuple(serial UInt32, order_id String)
```
Copy command
We can create a type with the corresponding names and types and slot it into
the foreign table:

```
1CREATE TYPE goal_type AS (serial bigint, order_id text);
2ALTER FOREIGN TABLE visits ALTER goals TYPE goal_type[];
```
Copy command
And now the Nested tuples translate to the composite type:

```
1try=# SELECT * FROM nest_bin.visits WHERE visit_id < 3 ORDER BY visit_id;
2 visit_id | user_id |        goals        
3----------+---------+---------------------
4        1 |       1 | {"(1,xx)","(2,yy)"}
5        2 |       2 | {"(3,aa)","(4,bb)"}
```
Copy command
Naturally we can also INSERT data in this format:

```
1INSERT INTO visits
2VALUES (3, 3, ARRAY[row(5, 'jj'), row(6, 'zz')]::goal_type[]);
```
