for insert events, the `before` fields are null. This message format is not compatible with our destination table `uk_price_paid` in ClickHouse. We can use a materialized view for transforming these messages at insert time. We show this below:

```
1CREATE MATERIALIZED VIEW uk_price_paid_mv TO uk_price_paid
2(
3   `id` Nullable(UInt64),
4   `price` Nullable(UInt32),
5   `date` Nullable(Date),
6   `postcode1` Nullable(String),
7   `postcode2` Nullable(String),
8   `type` Nullable(Enum8('other'=0, 'terraced'=1, 'semi-detached'=2, 'detached'=3, 'flat'=4)),
9   `is_new` Nullable(UInt8),
10   `duration` Nullable(Enum8('unknown'=0, 'freehold'=1, 'leasehold'=2)),
11   `addr1` Nullable(String),
12   `addr2` Nullable(String),
13   `street` Nullable(String),
14   `locality` Nullable(String),
15   `town` Nullable(String),
16   `district` Nullable(String),
17   `county` Nullable(String),
18   `version` UInt64,
19   `deleted` UInt8
20) AS
21SELECT
22   if(op = 'd', before.id, after.id) AS id,
23   if(op = 'd', before.price, after.price) AS price,
24   if(op = 'd', toDate(before.date), toDate(after.date)) AS date,
25   if(op = 'd', before.postcode1, after.postcode1) AS postcode1,
26   if(op = 'd', before.postcode2, after.postcode2) AS postcode2,
27   if(op = 'd', before.type, after.type) AS type,
28   if(op = 'd', before.is_new, after.is_new) AS is_new,
29   if(op = 'd', before.duration, after.duration) AS duration,
30   if(op = 'd', before.addr1, after.addr1) AS addr1,
31   if(op = 'd', before.addr2, after.addr2) AS addr2,
32   if(op = 'd', before.street, after.street) AS street,
33   if(op = 'd', before.locality, after.locality) AS locality,
34   if(op = 'd', before.town, after.town) AS town,
35   if(op = 'd', before.district, after.district) AS district,
36   if(op = 'd', before.county, after.county) AS county,
37   if(op = 'd', source.lsn, source.lsn) AS version,
38   if(op = 'd', 1, 0) AS deleted
39FROM default.uk_price_paid_changes
40WHERE (op = 'c') OR (op = 'r') OR (op = 'u') OR (op = 'd')
```

Notice our materialized view here selects the appropriate value for each column depending on the operation. The `version` is based on the `source.lsn` column, and we set the `deleted` column to 1, if the `op` column has a `d` value and 0 otherwise. The `op = r` value allows us to also support snapshot events if needed. This materialized view [can be simplified](https://github.com/ClickHouse/examples/blob/main/blog-examples/postgresql-cdc/views/create_update.sql) if delete support is not required.
