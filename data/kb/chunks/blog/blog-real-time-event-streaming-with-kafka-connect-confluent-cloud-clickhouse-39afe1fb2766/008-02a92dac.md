```
1SET flatten_nested=0
2CREATE TABLE ethereum.blocks
3(
4    `number` UInt32 CODEC(Delta(4), ZSTD(1)),
5    `hash` String,
6    `parent_hash` String,
7    `nonce` String,
8    `sha3_uncles` String,
9    `logs_bloom` String,
10    `transactions_root` String,
11    `state_root` String,
12    `receipts_root` String,
13    `miner` String,
14    `difficulty` Decimal(38, 0),
15    `total_difficulty` Decimal(38, 0),
16    `size` UInt32 CODEC(Delta(4), ZSTD(1)),
17    `extra_data` String,
18    `gas_limit` UInt32 CODEC(Delta(4), ZSTD(1)),
19    `gas_used` UInt32 CODEC(Delta(4), ZSTD(1)),
20    `timestamp` DateTime CODEC(Delta(4), ZSTD(1)),
21    `transaction_count` UInt16,
22    `base_fee_per_gas` UInt64,
23         `withdrawals_root` String,
24         `withdrawals` Nested(index Int64, validator_index Int64, address String, amount String) 
25)
26ENGINE = MergeTree
27ORDER BY timestamp
```

Equivalent schemas for the other data types can be found [here](https://github.com/ClickHouse/examples/tree/main/ethereum/streaming/schemas)

This above schema is alittle different than the schema proposed in our [earlier blog post](https://clickhouse.com/blog/clickhouse-bigquery-migrating-data-for-realtime-queries), with the columns `withdrawals_root` and `withdrawals` recently added to the specification[\[1]\[2]](https://ethereum.org/en/staking/withdrawals). We also set the setting `flatten_nested` to `0` to preserve the Nested structure of the `withdrawals` column. This allows us to insert this column as a nested JSON structure.
