### When local tables are the right answer \#

One pattern deserves special mention. Distributed tables are the right default for reading logs, but they need care when a query contains JOINs or subqueries.

Most log investigations only need to join or correlate data that's already local to a single cell. Consider a naive query like this:

```
1SELECT col1, col2
2FROM otel.generic_logs
3WHERE Region = 'us-east-1'
4  AND col3 IN (SELECT col4 FROM otel.generic_logs_0 WHERE ...)
```
Copy commandThe outer query still benefits from `optimize_skip_unused_shards` and only runs on the relevant cell. The subquery executes locally on that same cell against `generic_logs_0`, without distributed resolution.
