4. Now, we get into the conflict handling strategy in the case of updates. In an update record, `_peerdb_unchanged_toast_columns` is a comma\-separated string list of column names whose values are unchanged. If there are no such values, it will be an empty string like so.

```
1WHEN MATCHED -- row exists on target
2    AND src._peerdb_record_type != 2  -- this means it isn't a delete, so it's an update
3    AND _peerdb_unchanged_toast_columns = '' -- no unchanged toast columns, update everything
4    THEN
5        UPDATE
6        SET
7            "id" = src."id",
8            "blob" = src."blob",
9            "status" = src."status",
10            "_peerdb_synced_at" = CURRENT_TIMESTAMP

5. In the case above though, for instance, `blob` was unchanged in the update. That would then be handled like:

```
1WHEN MATCHED -- row exists on target
2    AND src._peerdb_record_type != 2 -- this means it isn't a delete, so it's an update
3    AND _peerdb_unchanged_toast_columns = 'blob' -- unchanged toast column ! we cannot update this guy, because it would wipe out its value to empty string sent by PG
4 THEN 
5        UPDATE
6        SET -- blob not updated here

8            "status" = src."status",
9            "_peerdb_synced_at" = CURRENT_TIMESTAMP
10            WHEN MATCHED
11            AND src._peerdb_record_type = 2 THEN DELETE
