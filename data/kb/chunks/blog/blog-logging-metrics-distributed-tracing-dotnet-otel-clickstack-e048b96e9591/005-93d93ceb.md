In .NET, OpenTelemetry builds on `System.Diagnostics`, so `ActivitySource` and `Meter` are the native primitives you use to create spans and metrics.

This is what it looks like in practice: the `PaymentProcessor` class creates child spans for each processing step:

```
1public async Task<PaymentResult> ProcessPaymentAsync(PaymentRequest request)
2{
3    var paymentId = Guid.NewGuid().ToString("N")[..12];
4		
5		// Start Activity for trace and enrich it with tags
6    using var activity = DiagnosticConfig.ActivitySource.StartActivity("process-payment");
7    activity?.SetTag("payment.id", paymentId);
8    activity?.SetTag("payment.order_id", request.OrderId);
9    activity?.SetTag("payment.amount", request.Amount);
10
11    // Step 1: Fraud check (creates its own child span)
12    var fraudScore = await RunFraudCheckAsync(paymentId, request);
13
14    // Step 2: Determine outcome based on configured rates
15    var outcome = DetermineOutcome();
16
17    // Step 3: Process the charge (creates its own child span)
18    var result = await ProcessChargeAsync(paymentId, request, outcome, fraudScore);
19
20    // Persist to SQLite (auto-instrumented by EF Core)
21    await using var db = await _dbFactory.CreateDbContextAsync();
22    db.Payments.Add(result);
23    await db.SaveChangesAsync();
24
25    // Record metrics
26    DiagnosticConfig.PaymentsProcessed.Add(1,
27        new KeyValuePair<string, object?>("status", result.Status),
28        new KeyValuePair<string, object?>("payment_method", request.PaymentMethod));
29
30    return result;
31}
```
