Note that we use [some](https://github.com/ClickHouse/ClickHouse/blob/23.4/src/Common/ProfileEvents.cpp#L147) keys from the [ProfileEvents](https://github.com/ClickHouse/ClickHouse/blob/23.4/src/Common/ProfileEvents.cpp) column in order to check the amount of data spilled to disk by external sorting during join processing:

```
1SELECT
2    query,
3    formatReadableTimeDelta(query_duration_ms / 1000) AS query_duration,
4    formatReadableSize(memory_usage) AS memory_usage,
5    formatReadableQuantity(read_rows) AS read_rows,
6    formatReadableSize(read_bytes) AS read_data,
7    formatReadableSize(ProfileEvents['ExternalProcessingUncompressedBytesTotal']) AS data_spilled_to_disk_uncompressed,
8    formatReadableSize(ProfileEvents['ExternalProcessingCompressedBytesTotal']) AS data_spilled_to_disk_compressed
9FROM clusterAllReplicas(default, system.query_log)
10WHERE (type = 'QueryFinish') AND hasAll(tables, ['imdb_large.actors', 'imdb_large.roles'])
11ORDER BY initial_query_start_time DESC
12LIMIT 1
13FORMAT Vertical;

We trigger external sorting for the join example query from above by setting `max_bytes_before_external_sort` to a lower threshold with the query’s SETTINGS clause:

```
1SELECT *
2FROM actors AS a
3JOIN roles AS r ON a.first_name = r.role
4FORMAT `Null`
5SETTINGS join_algorithm = 'full_sorting_merge', max_rows_in_set_to_optimize_join = 0, max_bytes_before_external_sort = '100M';
