## Creating an `ip_trie` Dictionary for IP Geolocation Data \#

In order to perform low\-latency IP lookups in ClickHouse, we'll leverage dictionaries to store `key -> attributes` mapping for our IP geolocation data in\-memory. ClickHouse provides an `ip_trie` [dictionary structure](https://clickhouse.com/docs/en/sql-reference/dictionaries#ip_trie) to map our network prefixes (CIDR blocks) to coordinates and country codes:

```
1create dictionary ip_trie (
2   cidr String,
3   latitude Float64,
4   longitude Float64,
5   country_code String
6) 
7primary key cidr
8source(clickhouse(table 'locip'))
9layout(ip_trie)
10lifetime(3600);
```

Dictionaries in ClickHouse are periodically refreshed based on the underlying table data and the [lifetime clause](https://clickhouse.com/docs/en/sql-reference/dictionaries#dictionary-updates) used above. In order to update our IP geolocation dictionary to reflect the latest changes in the DB\-IP dataset, we'll just need to reinsert data from the `locip_url` remote table to our `locip` table with transformations applied.

## Performing IP Lookups from an `ip_trie` Dictionary \#

Now that we have IP geolocation data loaded into our `ip_trie` dictionary (conveniently also named `ip_trie`), we can start using it for IP geolocation. This can be accomplished using the `dictGet` function as follows:

```
1dictGet(
2   '<dictionary name>',
3   ('field1','field2', .. .'fieldN'),
4   <ip address in type IPV4 or UInt>
5)
```
