A sibling typed MV projects the payload fields into columns, with the same (sym, t) sort key and EVEN distribution. Its queries implement the same Redshift drill\-down logic. Both representations were measured during the long run. **Observed outcome:**

Across the active\-ingestion comparison, the [typed alternative](https://github.com/ClickHouse/CostBench/blob/main/full-path-realtime/quotes/redshift-serverless/results/t2/charts/drilldown_query_latency_redshift_super_vs_typed_wide_summary.json) accumulated **2\.11× as much drill\-down runtime as the streaming view**. D1 was approximately equal; D2 was **4\.42× slower** on typed data. The primary article follows the faster measured alternative, which reads the streaming view.

**Cost boundary:**

The writer\-plus\-MSK preparation cost includes both child refreshes and is shared unchanged between the read alternatives. The score for the streaming view charges only its aggregate and drill\-down query allocations, rather than adding typed query executions.

**Interpretation:**

The benchmark measures the complete recorded query outcome. It does not isolate how much of the gap comes from background sorting, payload navigation, query formulation, or other engine work. A typed layout cannot be assumed faster from a short characterization when the complete run shows otherwise.

### Interactive aggregations over ordered pre\-aggregated data \#

Daily pre\-aggregations let [A1\-A4](https://clickhouse.com/blog/costbench-real-time-performance-per-dollar#the-continuous-query-workload) combine prepared counts, sums, and price minima and maxima. A1\-A2 filter summaries by symbol; A3\-A4 read across all symbols. ClickHouse reads current summaries; Redshift reads its last completed daily\-MV refresh. The chart compares aggregate latency as ingestion continues.

**ClickHouse Cloud:**

- **13 ms median** \- 34\.6× faster than Redshift Serverless
- **42 ms P99** \- 128× faster
- **111 ms maximum** \- 57\.2× faster

Accumulated runtime was **10\.21 seconds** across the 190 four\-query batches.

**Redshift Serverless:**

- **449\.4 ms median**
- **5\.32 s P99**
- **6\.35 s maximum**

Accumulated runtime was **12\.05 minutes** across the same 190 batches. These queries read refreshed summaries without waiting for the next update. ClickHouse served them faster while maintaining summaries during inserts; Redshift’s measured latency came with a refresh\-dependent freshness boundary.

> Across the interactive\-aggregation workload, ClickHouse Cloud was **70\.8× faster overall**, with summaries maintained during inserts.
