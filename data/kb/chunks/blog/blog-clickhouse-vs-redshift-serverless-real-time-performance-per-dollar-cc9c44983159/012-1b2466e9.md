**Query definitions:**

Part 1 describes A1\-A4 and D1\-D2\. The Redshift SQL preserves the symbol filter and full\-history scope, with engine\-specific substitutions. D1 uses window functions for first and last prices; D2 uses approximate discrete percentiles and moment calculations. Its excess\-kurtosis convention differs from ClickHouse’s raw population kurtosis, so strict numerical equivalence is not asserted for that field.

**Cache policy:**

[enable\_result\_cache\_for\_session](https://docs.aws.amazon.com/redshift/latest/dg/r_enable_result_cache_for_session.html) was off. Underlying data caches were allowed to operate normally; the benchmark did not flush them between queries.

**Timing:**

Redshift latency uses [SYS\_QUERY\_HISTORY.elapsed\_time](https://docs.aws.amazon.com/redshift/latest/dg/SYS_QUERY_HISTORY.html#SYS_QUERY_HISTORY-table-columns), converted to seconds; ClickHouse uses its recorded runner duration. Median, P99, and maximum pool unsmoothed per\-query observations with **0 \< raw\_rows ≤ 100 billion**. P99 uses linear interpolation. Accumulated runtime uses the same recorded timing basis.

**Latency charts:**

Each system is plotted at its own observed ingestion progress. Aggregate trends use a centered seven\-observation rolling median; drill\-downs use five observations, with shrinking edge windows. No outliers are removed. The curves are display smoothing; the statistics and accumulated totals use the original recorded durations.
