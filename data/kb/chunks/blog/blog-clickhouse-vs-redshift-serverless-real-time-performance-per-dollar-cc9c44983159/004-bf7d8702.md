ClickHouse Cloud used a 16\-CPU, 64\-GiB read node. Redshift used separate writer and reader workgroups connected by a live datashare. The reader was fixed at **32 RPUs**. RPUs are provider capacity units, not an assertion of identical CPU or memory resources. MSK used **three kafka.m7g.xlarge brokers**, **24 partitions**, replication factor three, and 500 GB of storage per broker.

**① Preparation cost:**

The model includes ClickHouse’s complete two\-node HA ingest service and Redshift’s writer plus MSK broker and storage costs. The accepted [writer\-capacity scenario](https://github.com/ClickHouse/CostBench/blob/main/full-path-realtime/quotes/redshift-serverless/costs/writer_capacity_assumption.json) prices **32 active RPUs** across the complete producer window. The original long run used 128 writer RPUs; subsequent characterization found that 32 sustained the target and 16 did not. The cost is modeled at 32; the recorded latency and freshness remain from the long run.

**② Query cost and ③ runtime:**

ClickHouse prices recorded query duration at its read\-side compute rate. Redshift allocates hourly reader compute\_seconds to statements in proportion to their recorded elapsed time, then prices the query allocations. Accumulated runtime sums the accepted query durations. The allocation represents query work, rather than reconstructing a complete invoice.

**Target versus observed rate:**

Redshift’s [completed run](https://github.com/ClickHouse/CostBench/blob/main/full-path-realtime/quotes/redshift-serverless/README.md) ingested all **113,219,565,734 rows** in **113,227 seconds**, about **31\.45 hours**, averaging **999,933 rows/s**. ClickHouse completed its ingest in about **36\.75 hours**, averaging approximately **0\.86 million rows/s**. The target was shared; observed progress differed. Kafka delivery, streaming\-view visibility, and child\-MV visibility are separate milestones.

**Reporting window:**

Per\-query latency plots stop at 100 billion rows. Preparation cost covers the complete producer window; accumulated query cost and runtime use the accepted active\-ingestion observations through the reference endpoint. Later query observations and freshness samples are excluded. The writer model also includes both child\-MV refresh paths, described below.

ClickHouse Cloud led in all three measured components:

- ① **Preparation cost:** $28\.69 versus $522\.03\.
- ② **Normalized query cost:** about $0\.05 versus $24\.97\.
- ③ **Accumulated query runtime:** 58\.12 seconds versus 1\.69 hours.
