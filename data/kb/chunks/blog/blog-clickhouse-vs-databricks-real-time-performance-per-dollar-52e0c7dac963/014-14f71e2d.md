### Accumulated query cost and runtime \#

The two query paths add up differently: drill\-downs account for most of Databricks’ accumulated runtime. The charts below combine both workloads and price their recorded durations using the benchmark’s read\-side cost model.

ClickHouse Cloud accumulated **56\.39 seconds** of query runtime and Databricks **29\.10 minutes**. Their normalized query\-serving costs were about **$0\.05** and **$2\.65**, respectively. These are costs for the query work, not complete warehouse invoices.

> **Across the query workload, ClickHouse Cloud was 31× faster overall, with 54\.2× lower normalized query cost.**

## From the field: Bullet \#

Bullet’s migration from Databricks to ClickHouse Cloud shows the production benefits of fresher data and faster queries for real\-time applications. The trading platform previously computed results hourly in Databricks and copied them into DynamoDB for serving, leaving users with data that was at least an hour old.

After the switch, query latency fell from **10–15 seconds to milliseconds**, and data freshness improved from **1–2 hours to under 5 seconds**. Bullet eliminated the separate DynamoDB serving layer while handling **1,000× more data** across three environments at comparable monthly cost. “We don’t even need a serving layer anymore,” says co\-founder Tristan Frizza. [Read Bullet’s migration story](https://clickhouse.com/blog/bullet-real-time-analytics).

CostBench evaluates that efficiency across the complete analytics path, from preparing incoming data to serving queries.

## Databricks can’t match ClickHouse Cloud for real\-time analytics \#

While fresh data kept arriving, ClickHouse Cloud led across the complete tested path:

**① Preparation cost: 24\.2× lower** for ingestion, ordering, and pre\-aggregation.  

**② Normalized query cost: 54\.2× lower** for the queries.  

**③ Accumulated query runtime: 31× lower** across both query workloads.
