## The fresh\-data path widens the performance\-per\-dollar gap \#

We began with a thesis:

> Under sustained load, keeping data query\-ready can shape performance per dollar as much as query execution itself.

The results now show just how large that impact can be.

### Query\-side performance: a 23–101× advantage \#

The earlier [query\-side comparison](https://clickhouse.com/blog/cloud-data-warehouses-cost-performance-comparison) began with an already\-loaded dataset and measured query\-serving cost and runtime. ClickHouse led that comparison: Databricks, Snowflake, Redshift Serverless, and BigQuery Capacity had query\-side scores **23–101× higher**.

This round asks a broader question: what happens to performance per dollar when fresh data keeps arriving and each system must prepare it while serving queries?

### End\-to\-end performance: a 412–1,996× advantage \#

In the continuous\-ingestion benchmark, Snowflake’s end\-to\-end score was **412× higher** than its matched ClickHouse baseline; BigQuery Capacity’s was **438×**, Databricks’ **752×**, and Redshift Serverless’ **1,996×**. Lower is better.

The larger range comes from a broader benchmark scope: data preparation and query serving running together. It shows how much the complete path can matter to performance per dollar.

### Why the complete path matters \#

The final chart brings runtime and cost together. ClickHouse Cloud combines the lowest accumulated query runtime with the lowest combined preparation and normalized query\-serving cost in the accepted comparisons.

Its fresh\-data path performs ordering and pre\-aggregation as incoming blocks are inserted. Raw data and summaries advance together, so queries can use current, prepared data without waiting for a separate summary\-refresh cycle.
