### Organize data for vectorized execution and chunk pruning \#

Columnar layouts also help the engine to process the data it reads efficiently. With a column’s values together in memory, the engine can apply an operation to a chunk of values in a simple loop. This [vectorized execution](https://www.cidrdb.org/cidr2005/papers/P19.pdf) reduces the overhead of handling rows individually. Suitable operations can also use [SIMD instructions](https://en.wikipedia.org/wiki/Single_instruction,_multiple_data), which process several values with one instruction.

Before reading a chunk of stored data, the engine checks its metadata and skips it when the metadata shows it cannot contain values matching the query’s filter. This is **chunk pruning**.

Our query already reads only `sym` and `day` columns. But in the unsorted example, AAPL quotes appear in all three chunks, so the engine must read all three.

[Sorting](https://en.wikipedia.org/wiki/Database_index#Clustered) by `sym` keeps each stock’s quotes together. For `WHERE sym = 'AAPL'`, the engine now reads **one AAPL chunk** and skips the MSFT and NVDA chunks. That leaves **three AAPL quotes** to group by day and count.

RESEARCH BACKGROUND: VECTORIZED EXECUTION (click to expand)

[*MonetDB/X100: Hyper\-Pipelining Query Execution*](https://www.cidrdb.org/cidr2005/papers/P19.pdf)
 (Boncz, Zukowski and Nes, CIDR 2005\) explains how processing chunks of values reduces tuple\-at\-a\-time interpretation overhead while avoiding the large intermediate results of whole\-column execution.
 

 This helps explain the distinction above: pruning reduces how much data the engine processes; vectorized execution makes processing the remaining data more efficient.
 

RESEARCH BACKGROUND: PHYSICAL ORDERING AND CHUNK PRUNING (click to expand)

[*C\-Store: A Column\-oriented DBMS*](https://www.vldb.org/archives/website/2005/program/paper/thu/p553-stonebraker.pdf) (Stonebraker et al., VLDB 2005\) describes storing columnar data in projections ordered by selected keys, supporting efficient searches and compression. [*Small Materialized Aggregates*](https://www.vldb.org/conf/1998/p476.pdf) (Moerkotte, VLDB 1998\) explains how compact summaries, including minimum and maximum values, let queries skip irrelevant blocks.
 

 Together, these ideas explain the example above: sorting by stock symbol concentrates each stock’s quotes into fewer chunks, and chunk metadata lets the engine identify which chunks it can skip.
