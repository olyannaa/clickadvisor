How does parallelized query throughput scale with CPU cores? (click to expand)

To test how this **parallel execution model scales with CPU cores**, we reran the two raw\-data drill\-down queries with **2, 4, 8, 16, 30, and 59 CPU cores available to each query**. All **113\.2 billion quotes** were already loaded and prepared. This was a separate experiment from the continuous\-ingestion measurements above.

At **59 cores**, throughput reached about **15\.56 GB/s** with hot caches and **9\.85 GB/s** with cold caches. Hot permits ordinary data caches and the query\-condition cache; cold bypasses data caches and disables the query\-condition cache. Query\-result caching remains disabled in both cases. **Speedups are not perfectly linear**: combining partial results adds work, even when that merging work is parallelized, and some query stages cannot be fully parallelized.

Source: [Measurements and methodology](https://github.com/ClickHouse/CostBench/blob/main/full-path-realtime/quotes/clickhouse-cloud/experiments/reader-thread-scaling/2026-10-11-cache-modes/README.md)

> **Parallelized execution on NVIDIA Vera:**  
> The same parallel execution model also automatically takes advantage of larger machines. On a dual\-socket NVIDIA Vera system with **176 CPU cores**, the ClickHouse engine delivered [the fastest ClickBench result we had ever measured](https://www.linkedin.com/posts/nvidia-ai-infra_nvidia-vera-cpu-fastest-machine-weve-activity-7501661486046523392-8T84). Our [Vera performance walkthrough](https://clickhouse.com/blog/clickhouse-performance-on-nvidia-vera) shows a CPU\-intensive aggregation running **about 164× faster with 176 cores than with one**. That is close to the **176× speedup of perfectly linear scaling**: combining partial results adds overhead, and some query stages cannot be fully parallelized.  
>   
> A separate filtering test processed **about 900 GB/s**, with further scaling limited by memory bandwidth. The walkthrough also shows how **SIMD accelerates supported operations within each core**.
