We could have used Docker or Podman to create the network namespace. However, we deliberately set it up manually using `netns` to make the network simulation easier to understand.

We then used `tc` (traffic control) to simulate a 32 ms WAN delay between the client and the server. We also configured the initial TCP congestion window to 8 MSS (`initcwnd 8`).

1. Have a ClickHouse binary (\< 26\.9\) (the one we use to reproduce the issue)

```
1mkdir -p ~/chbin && cd ~/chbin
2wget https://builds.clickhouse.com/26.8/amd64/clickhouse && chmod +x ./clickhouse
```
Copy command
2. Create a network to simulate the customer infrastructure (client and server \~32 ms apart).

```
1# Create a dedicated network namespace for ClickHouse
2sudo ip netns add chsrv
3
4# Create a virtual ethernet pair
5sudo ip link add veth-host type veth peer name veth-ch
6sudo ip link set veth-ch netns chsrv
7
8# Assign IP addresses
9sudo ip addr add 10.99.0.1/24 dev veth-host
10sudo ip link set veth-host up
11sudo ip netns exec chsrv ip addr add 10.99.0.2/24 dev veth-ch
12sudo ip netns exec chsrv ip link set veth-ch up
13sudo ip netns exec chsrv ip link set lo up
14
15# Add a 32ms egress delay and set initial cwnd to 8
16sudo ip netns exec chsrv tc qdisc add dev veth-ch root netem delay 32ms
17sudo ip netns exec chsrv ip route change 10.99.0.0/24 dev veth-ch \
18    proto kernel scope link src 10.99.0.2 initcwnd 8
```
Copy command
3. Verify the simulated network (you should see \~32 ms)

```
1ping -c 5 10.99.0.2
```
